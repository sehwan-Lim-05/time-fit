# Next.js 프리뷰 검증 및 운영 전환 게이트 (2026-09-19)

대상: PR #4 (`codex/nextjs-api-routing`), PR #3 위에 쌓인 변경. 운영 배포는 하지 않았다.

## 확인된 항목

- Vercel 프리뷰 빌드 Ready, 빌드 출력의 API 함수는 `api/[...route]` 한 개다.
- 로컬 브라우저에서 관리자 로그인·태블릿 연결 화면이 렌더링되고 콘솔 오류가 없었다.
- 프리뷰 `GET /api/tossplace`는 200, `POST /api/tossplace`의 빈 시험 JSON은 200을 반환했다. 이 웹훅은 현재 데이터 쓰기 없이 이벤트 식별자만 로그에 남긴다.
- 프리뷰의 `GET /api/check-attendance-alerts`, `GET /api/payroll-notifications`는 인증 없이 401을 반환했다.
- `GET /api/sync-sales`는 처음에는 설정 부재를 나타내는 503을 반환했다. 인증 검사를 설정 검사보다 앞으로 옮긴 뒤 최신 프리뷰에서 무인증 401을 재확인했고 회귀 테스트를 추가했다.
- 단위 테스트 59개 통과.

## 아직 통과하지 않은 게이트

1. Vercel 환경 변수 목록에서 `VITE_SUPABASE_*`, `SUPABASE_*`, `CRON_SECRET`, Toss 키 등이 **Production에만** 할당되어 있다. 프리뷰에는 인증 서비스와 데이터베이스 연결이 없으므로 실제 로그인, 권한별 API, 정상 Cron, 실매장 Toss 동기화는 검증하지 못했다. 운영 비밀값을 프리뷰로 복사하지 않는다. 격리된 테스트 사업장 및 별도 프리뷰 자격증명으로 검증해야 한다.
2. Toss 웹훅 수신기는 현재 요청 서명 검증 없이 POST를 수락한다. 지금은 로그만 쓰고 매출을 갱신하지 않지만, 이를 결제 확정 이벤트로 사용하기 전에 Toss의 공식 서명 규격에 따른 검증과 재전송·중복 처리 검증이 필요하다.
3. `npm audit --omit=dev`는 Next.js 15.5.25 및 기존 Supabase SDK 2.49.4의 하위 의존성에서 5건(낮음 2, 보통 1, 높음 2)을 보고한다. Next.js의 PostCSS·sharp, Supabase auth-js 관련 경고다. Next.js 자체의 최초 치명적 경고는 15.5.25로 제거했다. 무작정 메이저 업그레이드하기보다 로그인·이미지 처리 및 CSS 빌드를 포함한 호환성 회귀 후 패치한다.
4. 정상 Cron 실행은 실제 외부 서비스 호출·급여 알림 발송을 일으킬 수 있어 프리뷰에서 실행하지 않았다. 테스트 사업장, 격리된 메일/알림 공급자와 테스트 날짜가 준비된 뒤 수행한다.

## 운영 전환 순서

PR #3 및 #4를 순서대로 병합하기 전에 격리 프리뷰의 역할별 로그인, 무인증/소유자 API, Toss 시험 웹훅, 각 Cron의 인증 및 시험 작업, 데이터 범위, 배포 함수 수·실행 시간을 검증한다. 이후 보안 경고 처리 여부를 결정하고 운영 배포·롤백 배포를 준비한다.
