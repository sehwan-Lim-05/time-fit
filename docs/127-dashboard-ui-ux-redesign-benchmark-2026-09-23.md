# TimeFit 운영 대시보드 UI·UX 재설계안

작성일: 2026-09-23  
대상: 관리자 홈, 매출 분석, 지출·증빙, 급여 요약  
목표: 매장 관리자가 **10초 안에 상태를 판단하고, 1분 안에 조치까지 완료**할 수 있는 운영 대시보드

## 1. 결론

TimeFit 대시보드는 단순 지표판이 아니라 `오늘 처리할 업무`, `매장 성과`, `데이터 신뢰 상태`를 연결하는 운영 콘솔로 재설계한다.

핵심 원칙은 다음과 같다.

1. 첫 화면은 “현재 어떤 상태이고 무엇을 해야 하는가”에 답한다.
2. 금액만 크게 보여주지 않고 기준 기간, 전기 대비, 데이터 기준 시각을 함께 제공한다.
3. 정상 정보보다 예외와 미처리 업무를 먼저 보여주되 불필요한 경고는 줄인다.
4. 그래프는 장식이 아니라 원인 탐색 도구로 사용한다.
5. 매출·지출·급여·순익은 같은 기간과 같은 상태 언어를 사용한다.
6. 토스의 간결한 문장과 명확한 행동 설계는 참고하되, TimeFit에는 Shopify형 분석 계층과 업무 처리 흐름을 더한다.

### 2.2 차용할 것과 차용하지 않을 것

#### 차용할 것

- 토스: 한 화면 한 메시지, 쉬운 한국어, 주 행동 1개, 충분한 여백
- Toss Place: 날짜 범위와 KPI를 한 덩어리로 배치
- Shopify: KPI → 추이 → 원인 → 상세의 분석 순서
- Polaris: 색상 외 아이콘·부호·텍스트를 함께 쓰는 상태 표현
- Carbon: 고밀도 표에서도 필터와 열 의미가 흔들리지 않는 구조

#### 그대로 차용하지 않을 것

- 소비자 금융앱 수준의 과도한 여백: 데스크톱 운영 화면에서는 정보 탐색 비용이 커진다.
- 모든 지표의 카드화: 카드가 많아지면 중요도가 사라진다.
- 근거 없는 자동 인사이트: 수집 완결성이 없으면 비교와 원인 문장을 보류한다.
- 빨강/초록만으로 좋고 나쁨 표시: 매출 감소와 지출 감소는 의미가 반대일 수 있다.
- 홈 화면의 복잡한 편집 기능: 초기에는 역할별 기본 구성을 제공하고 개인화는 사용 데이터가 쌓인 뒤 도입한다.

## 3. 현재 대시보드 진단

### 강점

- 확인할 일, 매출 흐름, 오늘 출퇴근, 이번 주 스케줄이 한 홈에 연결되어 있다.
- 스케줄에 팀명이 아닌 근무자 이름과 수정·취소 행동이 노출된다.
- 매출 분석에 데이터 수집 상태와 비교 보류 개념이 구현되어 있다.

### 주요 문제

| 우선순위 | 문제 | 결과 |
|---|---|---|
| P0 | 홈의 카드들이 같은 시각적 무게를 가짐 | 사용자가 먼저 볼 항목을 판단해야 함 |
| P0 | 매출·지출·급여 상태가 서로 다른 언어와 기간을 사용 | 숫자 간 연결 관계를 한눈에 이해하기 어려움 |
| P0 | 데이터 최신성과 업무 미처리가 같은 경고 스타일에 섞임 | 시스템 문제와 사람의 할 일이 구분되지 않음 |
| P1 | 홈의 매출 요약이 로딩 중일 때 정보 가치가 급감 | 이전 정상값과 갱신 상태를 함께 보여줄 필요 |
| P1 | 스케줄이 많은 날은 홈 세로 길이가 급증 | 오늘/이번 주 핵심 인원과 예외만 요약해야 함 |
| P1 | 상세 분석의 표와 그래프 연결성이 약함 | 그래프 선택이 표 필터와 상세 패널에 이어져야 함 |
| P2 | 사용자 역할별 첫 화면 차이가 작음 | 대표, 매니저, 회계 담당자의 우선 업무가 다름 |

## 5. 홈 화면 상세 설계

### 5.1 전역 헤더

- 좌측: 현재 사업장, 다른 사업장 전환
- 중앙 또는 우측: `오늘 / 이번 주 / 이번 달` 범위 전환
- 우측: `마지막 갱신 22:24`, 알림, 계정
- 갱신 상태는 다음 네 종류만 사용한다.
  - 최신: `22:24 기준`
  - 진행: `매출 갱신 중`
  - 지연: `일부 데이터 지연`
  - 실패: `갱신 실패 · 다시 시도`

### 5.2 오늘의 운영 상태

큰 배너 대신 2열의 낮은 요약 패널을 사용한다.

```text
오늘 운영은 정상이에요                         [오늘 현황 보기]
근무 중 6명 · 지각 1건 · 미처리 증빙 3건
```

- 문장은 상태에 따라 자동 생성하되 한 문장만 노출한다.
- 정상일 때는 축하 일러스트보다 수치와 다음 행동을 우선한다.
- 문제가 여러 개면 금액 위험 > 급여 마감 > 근태 > 일반 확인 순으로 대표 이슈를 선택한다.

### 5.3 처리할 일

카드 나열 대신 하나의 작업 큐로 통합한다.

| 요소 | 규칙 |
|---|---|
| 심각도 | 긴급, 오늘, 확인 |
| 제목 | 명사형이 아니라 행동형: `영수증 3건을 확인해 주세요` |
| 설명 | 발생 기간과 영향 금액 표시 |
| 행동 | 행 전체 클릭 + 명확한 버튼 라벨 |
| 완료 | 홈에서 즉시 사라지거나 완료 피드백 제공 |

같은 종류가 많으면 한 행으로 묶고 `21건` 배지를 표시한다. 최대 5행을 기본 노출하고 나머지는 펼친다.

### 5.4 경영 요약

대표/재무 권한 사용자에게만 표시한다.

| KPI | 값 | 보조 정보 | 상태 |
|---|---:|---|---|
| 완료 매출 | 30,530,900원 | 전주 대비 금액·비율 | POS 마감 상태 |
| 확정 지출 | 12,430,000원 | 미확정 지출 별도 | 증빙 검토 상태 |
| 예상 인건비 | 8,210,000원 | 급여 초안 기준 | 재검토 필요 여부 |
| 예상 순익 | 9,890,900원 | 매출-지출-인건비 | 잠정/확정 |

규칙:

- 카드 전체를 색칠하지 않고 작은 상태 배지와 변화 화살표만 사용한다.
- 순익은 데이터 완결성에 따라 `잠정 순익` 또는 `확정 순익`으로 명명한다.
- 미증빙 카드 사용액은 지출 계산에는 포함하되 `미확정` 금액으로 분리한다.
- KPI를 누르면 같은 기간이 유지된 상세 화면으로 이동한다.

### 5.5 통합 손익 추이

- 기본 차트: 일별 매출·지출 막대 + 순익 선
- 보기 전환: 일간 / 주간 / 월간
- 범례: 완료 매출, 확정 지출, 미확정 지출, 인건비, 순익
- 차트 위에는 `이번 기간 순익이 감소한 가장 큰 수치 요인` 한 줄을 표시한다.
- 점이나 막대를 선택하면 오른쪽 상세 패널과 아래 거래 표가 같은 날짜로 필터링된다.
- 수집이 불완전한 기간은 점선과 `잠정` 배지로 표시한다.

### 5.6 현장 운영

홈에는 전체 주간 스케줄을 펼치지 않는다.

- 오늘 근무: 근무 중/예정/미출근/퇴근 완료 숫자
- 예외: 지각, 퇴근 누락, 승인 일정 없음
- 인원: 이름 앞에 `[주방] 최병주`처럼 소속 표시
- 주간 스케줄: 일별 총인원과 부족 인원만 7열 미니뷰로 제공
- 전체 이름과 수정·취소는 `스케줄 관리` 상세에서 제공

## 6. 상세 분석 화면 공통 구조

매출·지출·급여·순익에 동일한 뼈대를 사용한다.

```text
[제목] [기간] [상태]                           [내보내기] [주 행동]
데이터 기준 시각 · 포함 범위 · 산식

[KPI 1] [KPI 2] [KPI 3] [KPI 4]

[핵심 해석 1문장] [변동 요인 3개]

[주 차트 8] [구성/상태 4]

[필터]
[상세 표]
```

공통 규칙:

- `새로고침`은 화면 조회, `최신 데이터 동기화`는 외부 데이터 수집으로 구분한다.
- 내보내기는 `Excel`, `PDF 보고서`, `원본 CSV`를 메뉴로 묶는다.
- 모든 화면은 현재 기간과 비교 기간을 URL 또는 화면 상태로 유지한다.
- 상세 진입 후 뒤로가기를 하면 스크롤·탭·필터·선택 행을 복원한다.

## 7. 시각 디자인 시스템

### 7.1 디자인 성격

`차분한 운영 도구 + 명확한 금융 정보`를 목표로 한다. 토스의 친근함은 문장과 간격에서 가져오고, 과한 대형 타이포와 장식은 줄인다.

### 7.2 토큰

| 분류 | 권장값 |
|---|---|
| 페이지 배경 | `#F5F7FA` |
| 카드 배경 | `#FFFFFF` |
| 기본 글자 | `#191F28` |
| 보조 글자 | `#6B7684` |
| 비활성 글자 | `#ADB5BD` |
| 브랜드 | `#3182F6` |
| 브랜드 약색 | `#E8F3FF` |
| 성공 | `#0F9F6E` |
| 주의 | `#F59F00` |
| 위험 | `#E5484D` |
| 경계선 | `#E5E8EB` |
| 카드 반경 | 16px |
| 입력/버튼 반경 | 10~12px |
| 카드 그림자 | 기본 없음, 떠 있는 패널에만 약하게 적용 |
| 기본 간격 | 4, 8, 12, 16, 24, 32px 체계 |

### 7.3 타이포그래피

- 페이지 제목: 28/38, 700
- 섹션 제목: 20/28, 700
- KPI 값: 28~32/40, 700; 모바일 24/32
- 본문: 15/22, 400~500
- 보조 정보: 13/20, 400~500
- 숫자는 가능하면 tabular number를 사용해 열 정렬을 유지한다.
- 한 화면에서 굵은 글자 비율을 제한해 중요도 차이를 보존한다.

### 7.4 색상 의미

- 파랑: 선택·주 행동·중립적 핵심 지표
- 초록: 검증 완료·목표 달성
- 주황: 확인 필요·잠정 데이터
- 빨강: 실패·금액 위험·즉시 조치
- 매출 증가는 초록, 지출 증가는 자동으로 초록 처리하지 않는다. 지표 맥락에 따라 `유리/불리`를 별도로 계산한다.

## 8. 반응형 설계

### 데스크톱 1440px 이상

- 콘텐츠 최대폭 1440px
- KPI 4열
- 차트 8:4 분할
- 좌측 내비게이션 고정

### 태블릿 768~1439px

- KPI 2열
- 차트와 상세를 세로 배치
- 작업 큐는 2열 금지, 한 줄 목록 유지
- 표는 핵심 열을 고정하고 가로 스크롤 허용

### 모바일 767px 이하

- 상단 기간 선택을 스티키 처리
- KPI는 2열 또는 가로 스냅 스크롤
- 차트는 7일을 한 화면에 억지로 축소하지 않고 좌우 탐색 제공
- 표는 요약 행 + 상세 바텀시트로 변환
- 주 행동은 하단 고정 영역에 1개만 표시

## 9. 상태·빈 화면·오류 설계

| 상황 | 표시 방식 |
|---|---|
| 최초 로딩 | 실제 레이아웃과 같은 스켈레톤 |
| 백그라운드 갱신 | 기존 값 유지 + 작은 진행 표시 |
| 일부 실패 | 정상 데이터 유지 + 실패한 영역만 재시도 |
| 데이터 없음 | `0원`이 아니라 연결/수집/조건 없음 원인을 구분 |
| 비교 불가 | 비교값·증감률을 숨기고 `비교 보류` 및 이유 표시 |
| 권한 없음 | 비어 있는 카드 대신 해당 섹션 자체를 숨기거나 권한 안내 |
| 오래된 데이터 | 기준 시각을 주황 배지로 표시하고 동기화 행동 제공 |

## 10. 접근성·사용성 기준

- 본문 텍스트와 배경은 WCAG AA 대비를 충족한다.
- 색상만으로 상태를 표현하지 않고 아이콘, 부호, 문구를 함께 쓴다.
- 모든 그래프 데이터는 키보드 접근 가능한 표로도 제공한다.
- 탭과 토글은 `aria-pressed` 또는 올바른 탭 역할을 사용한다.
- 클릭 영역은 최소 44×44px를 확보한다.
- 포커스 링을 제거하지 않는다.
- 모션은 150~240ms 이내로 제한하고 `prefers-reduced-motion`을 지원한다.
- 금액은 우측 정렬하고 `원`, `건`, `%` 단위를 생략하지 않는다.

## 11. 역할별 기본 구성

| 역할 | 첫 번째 영역 | 두 번째 영역 | 숨김/축소 |
|---|---|---|---|
| 대표/최고관리자 | 경영 요약·순익 | 처리할 일 | 상세 근태는 축소 |
| 매장 관리자 | 오늘 운영·처리할 일 | 출퇴근·스케줄 | 급여 총액은 권한에 따라 표시 |
| 재무 담당 | 미증빙·카드·결산 | 매출·지출·순익 | 현장 스케줄 축소 |
| 부서 관리자 | 오늘 근무·승인 업무 | 부서 스케줄 | 전사 급여·순익 숨김 |

## 12. 구현 순서

### 1단계 — 공통 뼈대와 신뢰 상태

- 전역 기간 컨트롤과 데이터 기준 시각 통합
- KPI 카드, 상태 배지, 작업 큐 공통 컴포넌트화
- 로딩·오류·빈 상태 통일
- 매출/지출/급여/순익 용어와 상태 사전 확정

### 2단계 — 홈 재배치

- 오늘의 운영 상태와 처리할 일 통합
- 경영 KPI 4개 연결
- 홈 스케줄을 요약형으로 축소
- 권한별 영역 분기

### 3단계 — 통합 손익과 드릴다운

- 매출·지출·인건비·순익 통합 차트
- 날짜 선택과 상세 표 연동
- 미확정 지출, 급여 초안, 잠정 순익 상태 연결

### 4단계 — 상세 분석 일관화

- 매출·지출·급여·순익 상세 화면 공통 헤더와 필터 적용
- Excel/PDF/CSV 내보내기 패턴 통일
- 뒤로가기 시 화면 상태 복원

### 5단계 — 사용성 검증

- 대표, 매니저, 재무 담당 각 3명 이상 태스크 테스트
- `미처리 증빙 찾기`, `어제 순익 확인`, `매출 감소 원인 찾기` 완료 시간 측정
- 사용자 행동 로그 기반으로 카드 순서와 기본 펼침 상태 보정

## 13. 완료 기준

- 사용자가 로그인 후 10초 안에 오늘의 가장 중요한 상태를 말할 수 있다.
- 미처리 항목에서 상세 처리 화면까지 2번 이하 클릭으로 이동한다.
- 모든 금액에는 기간, 산식 또는 데이터 기준 상태가 연결된다.
- 비교 불완전 데이터에 증감률이나 자동 원인 문장이 노출되지 않는다.
- 데스크톱 첫 화면에서 오늘 상태, 처리할 일, 핵심 KPI가 스크롤 없이 보인다.
- 모바일에서 주요 행동과 필터가 겹치거나 화면 밖으로 잘리지 않는다.
- 키보드만으로 기간 변경, 탭 전환, 차트 데이터 확인, 상세 진입이 가능하다.
- 매출·지출·급여·순익 화면의 상태 배지와 용어가 동일하다.
